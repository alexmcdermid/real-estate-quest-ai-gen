# Developer Guide

## What this does

A GitHub Actions workflow runs weekly, picks a chapter of BC real estate licensing exam questions from a private question bank, sends them as few-shot examples to Claude Opus, receives a new original question back, validates it, and writes it to a dedicated Firebase project for review before it ever reaches the live site.

## Architecture (generation pipeline)

```
GitHub Actions (weekly cron or manual trigger)
  │
  ├── fetchQuestions.js
  │     └── reads {chapter}.js from private GitHub repo (real-estate-quest-questions)
  │         via Octokit + QUESTIONS_REPO_PAT (read-only)
  │
  ├── generateQuestion.js
  │     └── sends 10 random questions as few-shot context to Claude Opus
  │         receives one new question as JSON, validates structure and explanation format
  │
  └── writeToFirestore.js
        └── writes to questionsAiPending collection in real-estate-quest-ai Firebase project
            (separate from prod — service account cannot touch the production database)
```

### Firestore collections (real-estate-quest-ai project)

| Collection | Written by | Read by |
|---|---|---|
| `questionsAiPending` | this pipeline | real-estate-quest admin console (future) |
| `questionsAiApproved` | real-estate-quest admin (future) | real-estate-quest site (future) |

The generation pipeline only ever writes to `questionsAiPending`. Promotion to approved and integration into the live site are handled separately in the real-estate-quest project.

### Question schema

```json
{
  "chapter": 3,
  "questionNumber": 1,
  "question": "...",
  "choices": ["...", "...", "...", "..."],
  "correctChoice": 0,
  "premium": true,
  "explanation": "Correct Answer: 1\n\n...",
  "status": "pending",
  "generatedAt": "<Firestore server timestamp>"
}
```

- `correctChoice` is 0-based index into `choices`
- `explanation` always starts with `"Correct Answer: N"` where N = `correctChoice + 1` (1-based)
- `status` and `generatedAt` are added by `writeToFirestore.js`, not generated by the LLM

### Chapter rotation

Without a `CHAPTER_OVERRIDE`, `index.js` picks a chapter based on the ISO week number of the year, cycling through chapters 1–20. Chapter 1 runs on week 1, chapter 2 on week 2, etc., repeating every 20 weeks.

## Local setup

### 1. Clone and install

```bash
git clone <this repo>
cd real-estate-quest-ai-gen
npm install
cp .env.example .env
```

### 2. Anthropic API key

- Go to [console.anthropic.com](https://console.anthropic.com/)
- Create an API key
- Add to `.env`: `ANTHROPIC_API_KEY=sk-ant-...`

### 3. GitHub PAT (read-only access to questions repo)

- Go to GitHub → Settings → Developer Settings → Fine-grained personal access tokens
- New token scoped to the `real-estate-quest-questions` repo only
- Permission needed: **Contents: Read**
- Add to `.env`: `QUESTIONS_REPO_PAT=github_pat_...`

### 4. Firebase service account (AI project only)

- Create a new Firebase project: `real-estate-quest-ai` (separate from the prod project)
- Enable Firestore in that project
- Go to Project Settings → Service Accounts → Generate new private key
- Download the JSON file — **do not commit it**
- Paste the entire JSON as a single line into `.env`: `FIREBASE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}`

  To convert the JSON file to a single line:
  ```bash
  cat service-account.json | tr -d '\n'
  ```

### 5. Run locally

```bash
# Live run — generates a question and writes to Firestore
npm run dev

# Dry run — generates and logs the question, no Firestore write
DRY_RUN=true npm run dev

# Target a specific chapter
CHAPTER_OVERRIDE=5 npm run dev
```

## GitHub Actions secrets

Add these under **Settings → Secrets and variables → Actions** in this repo:

| Secret | Description |
|---|---|
| `ANTHROPIC_API_KEY` | Anthropic API key |
| `QUESTIONS_REPO_PAT` | Fine-grained GitHub PAT, read-only on real-estate-quest-questions |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Full service account JSON (single line) for real-estate-quest-ai project |

## Workflows

| Workflow | Trigger | Effect |
|---|---|---|
| `generate-questions.yml` | Weekly (Mon 9am UTC) + manual | Generates and writes to Firestore |
| `dry-run.yml` | Manual only | Generates and logs to Actions output, no write |

Both workflows accept an optional **Chapter** input when triggered manually.
